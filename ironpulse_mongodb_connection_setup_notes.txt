4.  Problems encountered and tests performed

Problem A: Initial Atlas connection failed with: MongoDB connection
failed: queryTxt ETIMEOUT cluster0.qxmfild.mongodb.net

Meaning: - The mongodb+srv:// URI requires DNS SRV and TXT lookups. -
The normal DNS resolver on this network was not returning the required
TXT record in time.

Test 1 — Google DNS TXT lookup: nslookup -type=TXT
cluster0.qxmfild.mongodb.net 8.8.8.8 Result: - DNS requests timed out.

Test 2 — Cloudflare DNS-over-HTTPS TXT lookup: curl.exe
“https://cloudflare-dns.com/dns-query?name=cluster0.qxmfild.mongodb.net&type=TXT”
-H “accept: application/dns-json” Result: - Successful JSON response. -
TXT record contained authSource=admin and
replicaSet=atlas-2dg53w-shard-0.

Test 3 — Cloudflare DNS-over-HTTPS SRV lookup: curl.exe
“https://cloudflare-dns.com/dns-query?name=_mongodb._tcp.cluster0.qxmfild.mongodb.net&type=SRV”
-H “accept: application/dns-json” Result: - Returned three MongoDB
server hostnames on port 27017:
ac-mbzeo4d-shard-00-00.qxmfild.mongodb.net
ac-mbzeo4d-shard-00-01.qxmfild.mongodb.net
ac-mbzeo4d-shard-00-02.qxmfild.mongodb.net

Test 4 — TCP connectivity: Test-NetConnection
ac-mbzeo4d-shard-00-00.qxmfild.mongodb.net -Port 27017 Result: -
TcpTestSucceeded: True - The first server’s port 27017 was reachable.

Test 5 — Node.js DNS-over-HTTPS: node -e
“fetch(’https://cloudflare-dns.com/dns-query?name=_mongodb._tcp.cluster0.qxmfild.mongodb.net&type=SRV’,{headers:{accept:‘application/dns-json’}}).then(r=>r.json()).then(d=>console.log(JSON.stringify(d.Answer,null,2))).catch(console.error)”
Result: - Successfully returned all three SRV records.

Test 6 — Node.js standard TXT lookup: node -e
“require(‘dns’).resolveTxt(‘cluster0.qxmfild.mongodb.net’,(err,records)=>console.log(err
|| records))” Result: - Error: queryTxt ECONNREFUSED
cluster0.qxmfild.mongodb.net

Test 7 — Resolved the three server hostnames: node -e “const
dns=require(‘dns’); const
hosts=[‘ac-mbzeo4d-shard-00-00.qxmfild.mongodb.net’,‘ac-mbzeo4d-shard-00-01.qxmfild.mongodb.net’,‘ac-mbzeo4d-shard-00-02.qxmfild.mongodb.net’];
hosts.forEach(h=>dns.lookup(h,(e,a)=>console.log(h,e?e.code:a)))”
Result: - ac-mbzeo4d-shard-00-00.qxmfild.mongodb.net -> 159.41.171.14 -
ac-mbzeo4d-shard-00-01.qxmfild.mongodb.net -> 159.41.171.28 -
ac-mbzeo4d-shard-00-02.qxmfild.mongodb.net -> 159.41.171.51

5.  Solution that worked Because SRV/TXT DNS lookups failed through the
    normal resolver, the .env MONGODB_URI was changed from the
    mongodb+srv:// format to a standard mongodb:// URI listing all three
    Atlas hosts explicitly, with TLS, replica set, and authentication
    source parameters.

Important connection settings used: - Protocol: mongodb:// - Port: 27017
for each host - TLS enabled - Replica set: atlas-2dg53w-shard-0 -
Authentication source: admin - Database path: ironpulse

The actual URI includes the database username and password. They are
intentionally NOT recorded in this document for security.

7.  Current code notes The main server/index.js uses dotenv, Express,
    and Mongoose; it checks that MONGODB_URI exists, connects with
    mongoose.connect(process.env.MONGODB_URI), then starts listening on
    the configured port. The earlier dns.setServers([“8.8.8.8”,
    “8.8.4.4”]) workaround did not solve the DNS problem and was removed
    for the DNS test. Check the current index.js before making further
